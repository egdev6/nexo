### PROPOSED derived acceptance - subject to approval

- A1 (S1-S3, S6, S8): Maintain EN/ES message catalogs in one canonical location, consumed by both
  frontend and native Rust without separate hand-maintained translations. Derive typed frontend keys;
  verify missing, extra, empty and mismatched-placeholder keys in both languages and native usage.
  Hub-owned copy, including titles, tooltips, accessible names, states and errors, uses these catalogs,
  not hard-coded strings in components or native menu builders. Bilingual onboarding copy also comes
  from the catalogs; brand names, language autonyms, identifiers and actual data are explicit exceptions.
- A2 (S2, S4, S5, S7): Keep the existing bilingual first-run screen, Spanish preselection and keyboard
  access. After an explicit choice and Continue, save `language` and `firstRunComplete` together via
  #16's existing settings patch queue. Only a successful save exposes the app list; failure keeps the
  picker and a retry in the selected language, without falsely completing onboarding or losing unrelated
  settings. This picker-local error language is a preview, not a persisted or global locale change.
- A3 (S2, S4, S6, S7): A locale hook derives its value from the existing hydrated `HubSettings.language`,
  not another independent preference or config store. In General, an EN/ES change updates the UI and
  native tray during the running session after the save succeeds, and remains selected after restart.
  Preserve the queued patch, retry and flush-on-exit guarantees. Failed saves retain recoverable pending
  work and do not claim the new locale was saved; rapid changes must not let older results win.
- A4 (S2, S6, S7): At startup Rust reads the validated #16 config through its existing Rust-owned store
  and locking/normalization rules before creating tray text, without waiting for the webview or writing
  a second config. Startup and frontend hydration must not disagree about a valid saved locale. A missing,
  corrupt, unreadable or future-version file uses safe Spanish for native bootstrap; preserve #16's
  recovery/read-only behavior and never overwrite the original implicitly. A fresh user still chooses.
- A5 (S2, S6, S7): Rebuild all hub-owned native tray labels on confirmed locale changes, including
  `Salir`, hub-only exit, unify/show/close and unresponsive labels, and localize hub-owned startup,
  connection and quit notices. Keep notice state structured enough to re-render an already-visible
  notice after a locale change; app-provided refusal reasons remain data, not translated guesses.
  Preserve app menu labels, IDs, checked/enabled state, action routes, registry updates and safe exit.
  If native refresh fails, report a recoverable localized error and retry; distinguish saved preference
  from failed application rather than claiming either success or an unsaved preference incorrectly.
- A6 (S3, S6, S8): Leave catalog-sourced names, descriptions, tags and news text, app-supplied menu
  labels/refusal reasons, user-supplied source labels and raw external diagnostics unchanged. Translate
  hub-generated news badges and CTA even where `catalog/mapping.ts` currently makes Spanish strings.
  Localize the built-in official source label without rewriting user-defined labels or stored data.
  Wrap external diagnostics in localized hub-owned context; do not claim the external text is localized.
- A7 (S6, S8): Format user-visible dates and numbers with the selected locale (`es-ES` / `en-US`),
  including plural-aware counts; retain identifiers, versions, raw catalog data and wire timestamps. Do not add a new date
  display merely to demonstrate formatting. Set document language for assistive technology and use
  appropriate language annotations for the deliberately bilingual picker.
- A8 (S8, S9): Port Quorb's catalog shape, dotted typed keys, interpolation, locale hook and test
  ideas without adding an i18n dependency by default. Recommend Quorb's locale -> Spanish -> key
  fallback for unexpected/missing values, but fail CI for missing catalog keys; fallback is not evidence
  of a complete translation.

### PROPOSED decisions and boundaries

- **D1, runtime locale:** recommend Spanish bootstrap, explicit bilingual first use, then the persisted
  confirmed language for both surfaces. Reuse #16's queue rather than Quorb's separate config listener;
  its `src/i18n/use-locale.ts` illustrates the hook and save-failure reconciliation, not Nexo's store.
- **D2, catalogs:** recommend Quorb's `src/i18n/es.ts`, `src/i18n/en.ts`, `src/i18n/index.ts` pattern
  and `src/i18n/i18n.test.ts` / `src/i18n/settings-nav.test.tsx` parity and view checks. Choose a shared
  representation or generated native artifact from the same source; never maintain a second Rust copy.
- **D3, installer:** recommend deferring handoff to a separately approved release/installer task.
  Quorb's `src-tauri/src/installer_locale.rs` consumes a bounded, version-checked one-shot choice and
  applies it only to fresh config; failed/invalid handoff falls back to the picker, never overwrites
  an existing config. If later adopted, decide separately whether installer choice fulfills S5 and
  test failure/reinstall cases. No installer work or release is authorized here.
- **D4, native failure and external data:** recommend structured hub-owned notices, localized on
  display, and a visible retry for failed tray refresh; keep provider text verbatim. Confirm this
  boundary and the UI for an already-saved language whose native menu could not be refreshed.
- #11 lists #17 as planned, ordered after #13 and #16, with original body authoritative. #13 and #16
  were closed in the read snapshot; code at `95b2209` already has #16's Rust config and picker wiring.
  Closure alone is not proof of integration. Refresh dependencies, assignees, comments and related PRs
  before publication or start; the draft itself does not establish availability or readiness.

### PROPOSED future verification - not run

- Catalog tests: type-check invalid keys; compare all EN/ES/native keys, nonempty values and placeholders;
  exercise fallback, interpolation, plurals and deterministic `Intl` dates/numbers with fixed timezone.
- View tests: render first use, all settings tabs, installed/connected apps, catalog, news, loading,
  empty and error states in each locale, including aria-label/title and keyboard behavior. Assert exact
  expected localized copy and unchanged external fixtures. Add a bounded static check for untranslated
  hub-owned literals in views and native labels, with reviewed data/brand/autonym exceptions.
- Lifecycle tests: delayed hydration; choice and failed write/retry; reload and restart; EN to ES and
  ES to EN; interleaved language and other changes, save failure/quit flush; corrupt/unreadable/future
  config protected; already-visible notices, refresh failure/retry and rapid menu rebuild ordering.
- Native tests: every hub-owned label and notice in EN/ES, initial tray without a webview, app-provided
  text untouched, menu checked/enabled values, routing and stale actions, registry and safe-exit behavior.
- Real Windows: isolated test profile, fresh choice in each language, tray before/after choice, all views,
  accessible text, app submenu and refusal/timeout/hub-only notice; switch both ways without restarting,
  quit/restart and verify persistence. Record OS/build, screenshots, gaps and Windows CI result.
